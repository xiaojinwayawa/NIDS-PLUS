# 网络入侵检测系统（NIDS）系统说明文档

## 一、系统概述

### 1.1 系统简介

网络入侵检测系统（Network Intrusion Detection System, NIDS）是一个基于机器学习和深度学习的实时网络安全威胁检测平台。该系统采用前后端分离架构，集成多种AI模型（LightGBM、XGBoost、CNN、GRU、Transformer等），支持实时流量捕获、流级特征提取、模型推理、告警生成和模型可解释性分析等完整功能链路。

### 1.2 系统定位

本系统面向网络安全研究和实际应用，提供：
- **实时检测能力**：支持PCAP文件回放和实时网卡流量捕获
- **多模型融合**：传统机器学习与深度学习模型的混合推理
- **可复现实验**：标准化的实验框架支持模型对比研究
- **可解释性分析**：基于SHAP值的模型决策解释
- **人机协同学习**：误报反馈机制支持模型持续优化

### 1.3 系统版本

- **当前版本**：v1.0.0
- **开发框架**：FastAPI + Vue 3
- **部署方式**：Docker Compose / 本地开发

## 四、核心功能模块

### 4.1 检测引擎（Detection Engine）

检测引擎是系统的核心组件，负责协调整个检测流水线。

#### 4.1.1 引擎状态机

```
IDLE → RUNNING → STOPPING → STOPPED
         ↓
       ERROR
```

| 状态 | 说明 |
|------|------|
| IDLE | 空闲状态，等待启动 |
| RUNNING | 运行中，正在处理流量 |
| STOPPING | 正在停止，清理资源 |
| STOPPED | 已停止 |
| ERROR | 错误状态 |

#### 4.1.2 流水线处理

```
Redis Queue → Flow Aggregation → Feature Extraction → Inference → Rule Correction → Alert → SHAP
```

**关键参数**：
- `BATCH_SIZE`: 100（每批处理数据包数）
- `INFERENCE_INTERVAL_MS`: 50（推理间隔）
- `ALERT_THRESHOLD`: 0.5（告警置信度阈值）
- `MAX_QUEUE_SIZE`: 10000（最大队列长度）

#### 4.1.3 流量源模式

| 模式 | 说明 | 配置项 |
|------|------|--------|
| pcap | PCAP文件回放 | `PCAP_FILE_PATH` |
| live | 实时网卡捕获 | `NETWORK_INTERFACE` |

#### 4.1.4 流级检测

检测引擎支持流级别（Flow-level）的网络入侵检测，相比传统的包级别检测具有以下优势：

**流聚合机制**：
- 基于5元组（src_ip, dst_ip, src_port, dst_port, protocol）聚合数据包
- 支持TCP/UDP/ICMP协议差异化超时管理
- 双向流跟踪，完整记录流的前向和后向特征

**流状态管理**：
```
ACTIVE → IDLE → FINISHED/TIMEOUT
```

**背景噪声过滤**：
- 过滤包数量低于阈值的微小流（默认`FLOW_MIN_PACKETS=3`）
- 减少系统背景噪声导致的误报

**流特征提取**：
- 提取78维CIC-IDS2017标准流特征
- 支持FIN/RST标志立即关闭流
- 定期清理过期流，防止内存泄漏

#### 4.1.5 规则修正机制

检测引擎集成规则引擎，在模型推理后进行攻击类型修正：

**工作流程**：
```
ML模型预测攻击 → 规则引擎匹配条件 → 验证流量特征 → 修正攻击类型 → 生成告警
```

**应用场景**：
- ML模型正确检测到攻击，但分类类型不准确
- 基于专家知识提高攻击类型识别精度
- 支持运行时动态启用/禁用

#### 4.1.6 流量统计

检测引擎实时收集流量统计信息：
- 协议分布统计
- 源/目的IP地址分布
- 源/目的端口活动统计
- 端口活动时间热力图数据

### 4.2 流量捕获模块（Traffic Capture）

#### 4.2.1 PCAP回放捕获（PcapReplayCapture）

- 从PCAP文件读取数据包
- 支持循环播放
- 可配置播放间隔（默认0.001秒）

#### 4.2.2 实时捕获（LiveCapture）

- 监听指定网卡接口
- 实时捕获网络流量
- 需要管理员权限（NET_ADMIN, NET_RAW）

### 4.3 流聚合模块（Flow Aggregator）

将网络数据包聚合为流（基于5元组），提取流级特征。

#### 4.3.1 流标识（5元组）

```
src_ip + dst_ip + src_port + dst_port + protocol
```

#### 4.3.2 流状态机

```
ACTIVE → IDLE → FINISHED/TIMEOUT
```

#### 4.3.3 流超时配置

| 协议 | 超时时间 | 说明 |
|------|----------|------|
| TCP | 120秒 | 支持FIN/RST立即关闭 |
| UDP | 120秒 | 无连接状态 |
| ICMP | 120秒 | 控制报文 |

#### 4.3.4 流特征提取

提取78维CIC-IDS2017标准特征，包括：
- 包统计（前向/后向包数、字节数）
- 包长度统计（均值、标准差、最大/最小值）
- 到达时间间隔（IAT）统计
- TCP标志位计数（SYN、FIN、RST等）
- 窗口大小统计
- 活跃/空闲时间统计

#### 4.3.5 背景噪声过滤

- `FLOW_MIN_PACKETS`: 3（最小包数阈值）
- 过滤微小流，减少误报

### 4.4 特征提取模块（Feature Extractor）

#### 4.4.1 支持的数据集类型

| 数据集 | 特征维度 | 说明 |
|--------|----------|------|
| CIC-IDS2017 | 78维 | 标准流特征 |
| NSL-KDD | 41维 | 传统数据集 |

#### 4.4.2 特征预处理

- **标准化**：StandardScaler
- **缺失值处理**：填充0
- **异常值处理**：替换无穷值为0
- **特征对齐**：确保训练和推理特征一致

### 4.5 推理引擎（Inference Engine）

支持多种模型类型的推理，包括单模型和模型融合。

#### 4.5.1 支持的模型类型

| 模型类型 | 框架 | 说明 |
|----------|------|------|
| LightGBM | LightGBM | 梯度提升树，推理速度快 |
| XGBoost | XGBoost | 极端梯度提升 |
| CNN | TensorFlow/Keras | 一维卷积神经网络 |
| CNN_ResAttn | TensorFlow/Keras | 带残差注意力的CNN |
| GRU | TensorFlow/Keras | 门控循环单元 |
| Transformer | TensorFlow/Keras | 注意力机制模型 |
| Fusion | 自定义 | 多模型融合 |

#### 4.5.2 模型融合策略

| 策略 | 说明 |
|------|------|
| Voting | 硬投票（多数表决） |
| Weighted | 加权平均概率 |
| Cascade | 级联（ML优先，DL处理不确定样本） |
| Stacking | 元学习器融合 |

#### 4.5.3 推理输出

```json
{
  "predictions": [0, 1, 0, ...],
  "confidences": [0.12, 0.89, 0.34, ...],
  "attack_types": ["Normal", "DDoS", "Normal", ...],
  "inference_time_ms": 15.2,
  "fusion_strategy": "weighted"
}
```

### 4.6 告警引擎（Alert Engine）

#### 4.6.1 告警生成逻辑

- 二分类：预测为1（攻击）且置信度 > 阈值
- 多分类：预测为攻击类别
- 高置信度异常：即使预测为正常，但置信度超过阈值也告警

#### 4.6.2 告警事件管理

| 参数 | 默认值 | 说明 |
|------|--------|------|
| ALERT_EVENT_COOLDOWN_SECONDS | 15 | 告警冷却时间 |
| ALERT_EVENT_RESOLVE_TIMEOUT_SECONDS | 30 | 告警自动解决超时 |

**事件状态**：
- `active`：活跃告警
- `resolved`：已解决（超过超时时间）

**事件合并**：
- 相同源IP + 攻击类型的告警在冷却时间内合并
- 记录重复次数（repeat_count）
- 更新首次/末次告警时间

#### 4.6.3 误报管理

- 支持用户标记误报（False Positive）
- 误报特征保存到CSV：`data/fp_governance/human_feedback_fp.csv`
- 支持误报反馈注入训练数据（Human-in-the-Loop）
- 误报取消时自动移除对应特征

### 4.7 SHAP分析模块（SHAP Analyzer）

#### 4.7.1 支持的解释器

| 解释器 | 适用模型 | 特点 |
|--------|----------|------|
| TreeExplainer | LightGBM/XGBoost | 快速，专为树模型优化 |
| KernelExplainer | 任意模型 | 通用但较慢 |
| DeepExplainer | 深度学习 | 专为神经网络设计 |

#### 4.7.2 输出内容

```json
{
  "base_value": 0.5,
  "top_features": [
    {
      "feature": "Flow_Duration",
      "value": 1234.5,
      "shap_value": 0.15,
      "contribution": "positive"
    }
  ],
  "calculation_time_ms": 5.2
}
```

### 4.8 训练模块（Training Module）

#### 4.8.1 支持的模型训练

| 模型类型 | 训练方式 | 进度回调 |
|----------|----------|----------|
| LightGBM | lgb.train() | 自定义回调 |
| XGBoost | xgb.train() | TrainingCallback |
| CNN/GRU/Transformer | DeepLearningTrainer | 异步进度更新 |

#### 4.8.2 训练流程

```
加载数据(10%) → 数据分割(15%) → SMOTE(可选) → 模型训练(15-85%) → 评估(90%) → 保存(100%)
```

#### 4.8.3 特征对齐机制

训练时自动对齐到78维CIC-IDS2017标准特征：
- 缺失列填充0
- 多余列丢弃
- 列名空格清理

#### 4.8.4 类别不平衡处理

- **SMOTE**：合成少数类过采样
- **类别权重**：class_weight计算
- **Focal Loss**：深度学习专用损失函数

### 4.9 实验模块（Experiment Runner）

#### 4.9.1 实验配置

```python
ExperimentConfig:
  experiment_name: str
  dataset_type: 'nsl-kdd' | 'cic-ids2017'
  model_types: List[str]
  random_seed: int = 42
  test_size: float = 0.2
  ml_num_boost_round: int = 100
  dl_epochs: int = 50
  dl_batch_size: int = 64
  dl_learning_rate: float = 0.001
  fusion_strategy: 'voting' | 'weighted' | 'cascade'
  use_focal_loss: bool = True
  use_class_weights: bool = True
  use_one_hot: bool = True
  use_human_feedback: bool = True
  is_multiclass: bool = False  # 是否启用多分类模式
```

#### 4.9.2 实验类型

| 实验类型 | 说明 |
|----------|------|
| ML-only | 仅传统机器学习模型 |
| DL-only | 仅深度学习模型 |
| Hybrid | ML+DL混合融合 |

#### 4.9.3 数据集预处理

**NSL-KDD**：
- 二分类：normal=0, attack=1
- 多分类：保持原始攻击类型标签
- 支持One-Hot编码
- 41维特征

**CIC-IDS2017**：
- 二分类：BENIGN=0, Attack=1
- 多分类：保持原始攻击类型（DDoS、PortScan、BruteForce等）
- 自动降采样（最大500,000样本）
- 78维特征对齐
- 支持多文件选择加载

#### 4.9.4 实验结果存储

- 路径：`data/experiments/`
- 格式：JSON
- 命名：`{experiment_name}_{hash}_{timestamp}.json`

#### 4.9.5 模型晋升机制

实验模型可晋升为正式模型：
- 复制到`models/`目录
- 更新数据库记录
- 生成元数据文件

#### 4.9.6 多分类支持

实验模块同时支持二分类和多分类实验，通过 `is_multiclass` 配置参数切换：

**二分类模式**（`is_multiclass=False`）：
- 所有攻击类型统一标记为"Attack"
- 适用于正常/异常检测场景
- 使用 `ExperimentRunner` 类

**多分类模式**（`is_multiclass=True`）：
- 保持原始攻击类型标签
- 支持细粒度攻击分类识别
- 使用 `MulticlassExperimentRunner` 类
- 支持Macro-F1、Weighted-F1等多分类指标
- 两个模式完全独立，互不影响

#### 4.9.7 人机协同学习

- 支持误报反馈注入训练数据
- 人工标记的误报样本自动过采样（默认100倍）
- 反馈数据存储在 `data/fp_governance/human_feedback_fp.csv`

### 4.12 规则引擎模块（Rule Engine）

规则引擎提供基于专家知识的推理后攻击类型修正功能。

#### 4.12.1 功能概述

- **推理后修正**：在ML模型检测到攻击但分类不准确时，基于规则修正攻击类型
- **JSON配置**：规则以JSON格式存储，支持动态加载和更新
- **专家知识库**：内置DDoS、端口扫描等常见攻击的检测规则
- **可配置开关**：支持运行时启用/禁用规则修正功能

#### 4.12.2 规则结构

```json
{
  "id": "RULE_DDOS_001",
  "name": "DDoS Flood Detection",
  "description": "High packet rate DDoS attack targeting web ports",
  "priority": 1,
  "conditions": {
    "Destination Port": {"in": [80, 443, 8080, 8000]},
    "Flow Packets/s": {"min": 1000},
    "Total Fwd Packets": {"min": 50},
    "Total Backward Packets": {"max": 10}
  },
  "correction": "DDoS"
}
```

#### 4.12.3 内置规则

| 规则ID | 攻击类型 | 说明 |
|--------|----------|------|
| RULE_DDOS_001 | DDoS | 高包率DDoS攻击（目标Web端口） |
| RULE_DDOS_002 | DDoS | 高字节率DDoS攻击 |
| RULE_PORTSCAN_001 | PortScan | 端口扫描检测（多端口尝试） |
| RULE_BRUTEFORCE_001 | BruteForce | 暴力破解检测 |

#### 4.12.4 工作流程

```
ML模型预测 → 规则匹配检查 → 条件验证 → 应用修正 → 最终攻击类型
```

#### 4.12.5 配置与使用

```python
# 在DetectionEngine中启用规则修正
self.rule_engine = RuleEngine()
self.rule_engine.set_enabled(True)

# 规则配置文件路径
# backend/config/rules.json
```

## 十七、已知限制

### 17.1 性能限制

- 单线程检测引擎（Python GIL限制）
- 深度学习推理依赖GPU（可选）
- 大文件PCAP回放速度受限

### 17.2 功能限制

- SHAP分析仅支持单样本（原型限制）
- 模型融合需手动配置权重

### 17.3 部署限制

- Docker需要特权模式（网络捕获）
- Windows需要Npcap驱动
- 生产环境需配置CORS
